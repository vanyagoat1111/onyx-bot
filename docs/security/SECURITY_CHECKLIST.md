## Сегодня, 20 минут

### 1. Задать три секрета в Vercel

Project → Settings → Environment Variables, окружение Production.

Сгенерировать каждый отдельно:

```
openssl rand -hex 32
```

Если под рукой нет терминала — подойдёт любой генератор длинной случайной строки.
Одинаковые значения использовать нельзя.

- [ ] `WEBHOOK_SECRET` — без него админ-функции бота отключены
- [ ] `CRON_SECRET` — без него не работают автодожимы и плановые аудиты
- [ ] `SHEETS_SECRET` — общий секрет с таблицей

### 2. Перерегистрировать вебхук с секретом

Одной строкой, подставив свой токен, домен и значение `WEBHOOK_SECRET`:

```
curl -F "url=https://ВАШ-ДОМЕН/telegram" \
     -F "secret_token=ЗНАЧЕНИЕ_WEBHOOK_SECRET" \
     -F "drop_pending_updates=true" \
     https://api.telegram.org/botТОКЕН/setWebhook
```

Проверить, что применилось:

```
https://api.telegram.org/botТОКЕН/getWebhookInfo
```

В ответе должно быть `"has_custom_certificate": false` и ваш адрес в `url`.

- [ ] вебхук зарегистрирован с `secret_token`
- [ ] бот отвечает на `/start`
- [ ] админ-команда работает (значит источник подтверждается)

### 3. Прописать секрет в Apps Script

Расширения → Apps Script → Настройки проекта (шестерёнка) → Свойства скрипта →
Добавить свойство:

- имя: `SHARED_SECRET`
- значение: то же, что в `SHEETS_SECRET`

Затем Развернуть → Управление развёртываниями → Изменить → Версия: новая → Развернуть.

- [ ] свойство добавлено
- [ ] скрипт переразвёрнут (иначе изменения не применятся)
- [ ] заявка из бота долетела до таблицы

### 5. Проверить историю коммитов на секреты

Из песочницы я git не запускал, чтобы не повредить репозиторий. Сделайте локально:

```
git log -p -S "BOT_TOKEN" -- . | head -50
git log -p -S "script.google.com/macros" -- . | head -50
```

Если найдётся реальный токен — недостаточно удалить файл: значение остаётся в
истории. Нужно **перевыпустить** ключ:

- токен бота — `/revoke` у @BotFather, затем `/token`;
- Upstash — Console → Database → Reset token;
- адрес Apps Script — Развернуть → Новое развёртывание (адрес сменится).

- [ ] история проверена
- [ ] найденное перевыпущено

## В течение месяца

### 8. Простейший CI

`.github/workflows/ci.yml` с одним шагом — прогон самопроверки:

```yaml
name: CI
on: [push, pull_request]
jobs:
  selftest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: python3 tools/selftest.py
```

Это уже закроет главный риск — выкатить сломанную воронку.
