# THREAT_MODEL — ONYX

Модель угроз для Telegram-бота, сайта и таблиц Google. Составлена 28 июля 2026.

## Что защищаем

**Персональные данные клиентов.** Имя, телефон, e-mail, ИНН, КПП, юридический адрес,
название компании, адрес сайта, загруженные файлы и видео-отзывы. Утечка означает
ответственность по 152-ФЗ и потерю доверия.

**Управление воронкой.** Статусы заказов, отметки оплаты, рассылки. Захват означает,
что чужой человек может писать от имени ONYX всей базе клиентов.

**Секреты.** Токен бота, токен базы, адрес веб-приложения Apps Script, ключ ИИ-провайдера.
Токен бота — самое ценное: он даёт полный доступ к переписке со всеми клиентами.

**Доступность.** Бот — единственный канал приёма заявок. Простой означает потерянные
деньги.

## От кого защищаем

**Внешний злоумышленник без доступа.** Знает только публичные адреса: домен функции
(виден в ссылках на картинки и чек-лист), имя бота, сайт. Мотив — спам, вымогательство,
кража базы контактов конкурента, использование инфраструктуры как прокси.

**Недобросовестный клиент.** Легально начал диалог с ботом. Может вводить произвольный
текст в анкету, слать файлы, жать кнопки в любом порядке и подставлять чужие
идентификаторы в `callback_data`. Мотив — получить услугу бесплатно, навредить,
достать данные других клиентов.

**Конкурент.** Заинтересован в базе контактов и в том, чтобы бот перестал работать
в рабочее время.

**Скомпрометированный администратор.** Телефон с Telegram украден или разблокирован.
Все административные функции доступны без дополнительного подтверждения.

**Случайная утечка.** Скриншот с адресом Apps Script в переписке, токен в логе,
секрет в истории коммитов. Самый частый сценарий на практике.

## Карта угроз

| Угроза | Как реализуется | Что защищает сейчас | Пробел |
|---|---|---|---|
| Захват административных прав | подделка апдейта с чужим `from.id` | заголовок-секрет, если задан | C2: без переменной защита выключена |
| Массовая рассылка от лица ONYX | вызов `/cron` из браузера | ничего | C1 |
| Разведка внутренней сети | адрес приватного диапазона в аудите | ничего | C3 |
| Кража чужих ПДн из таблицы | формула `IMPORTXML` в поле анкеты | ничего | H1 |
| Фишинг оператора | ссылка в тексте анкеты, которую увидит админ | ничего | H2 |
| Отказ в обслуживании | поток запросов от одного пользователя | ничего | H3 |
| Запись мусора в таблицы | прямой POST на адрес Apps Script | секретность адреса | H4 |
| Кража сессии на сайте | XSS через сторонний скрипт | ничего | H5 |
| Подмена данных чужого заказа | подстановка чужого ID в `callback_data` | проверки владельца в коде заказов | требует отдельной проверки |
| Утечка через логи | исключение на строке с телефоном | обрезка до 180 символов | M4, M5 |

## Границы доверия

1. **Интернет → функция бота.** Всё, что приходит на `/telegram` и `/cron`, недоверенное,
   пока не подтверждено секретом. Сейчас граница дырявая в двух местах.
2. **Функция → Apps Script.** Односторонний канал без взаимной аутентификации.
   Скрипт доверяет всему, что пришло.
3. **Функция → внешний сайт клиента (аудит).** Единственное место, где бот сам ходит
   по адресу, полученному от пользователя. Требует самых строгих ограничений.
4. **Клиент → анкета → таблица.** Текст проходит через две системы, каждая из которых
   интерпретирует его по-своему: Telegram как HTML, Sheets как формулу.

## Что считаем приемлемым риском

- Адрес веб-приложения Apps Script остаётся в роли секрета: перевод на полноценную
  аутентификацию потребует переписывания интеграции. Компенсируем общим секретом
  в теле запроса.
- Google Sheets как основное хранилище. Для текущего объёма это осознанный выбор;
  план перехода на настоящую базу описан отдельно, если нагрузка вырастет.
- Отсутствие второго фактора у администратора: Telegram сам по себе защищён
  паролем облака, дополнительный фактор в боте усложнит ежедневную работу.
  Компенсируем журналом административных действий.
